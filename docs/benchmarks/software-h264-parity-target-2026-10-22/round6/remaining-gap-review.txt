Remaining native/Go H264 gap — source review, 2026-10-22

Scope and limits
Frozen round5 already includes intra-word DC/H/V stores, packed CAVLC tables/common-write inlining, SSSE3 chroma, AVX2 quantFourMax, SSSE3 intra VAA, the SAD16 schedule, checked SAD pointers, and quarter candidate validation amortization. The round-six milestone incorporates center pairs, transform ABI and Hadamard; they are excluded from the remaining proposals below. This source review used the earlier round-five profiling boundary. No builds, tests, timings or profiles were run for this review.

The earlier matched codec-native-benchstat.txt checkpoint reports Road QP20/one slice at 30.75 ms Go versus 19.12 ms native (~61% longer Go time). That requires ~38% of Go time to disappear to reach native, not a 61% reduction. This is not a fresh measurement of the round-six changes. Four-slice wall time conceals some CPU cost: the same checkpoint has ~31.50 versus 20.03 CPU ms/frame. Small kernel wins cannot establish parity.

round5-road1-top.txt/cum.txt identify where Go spends time; native-road1-flat.txt shows native's corresponding hot paths. Their percentages/seconds are NOT directly comparable speed measurements: profiler, total runtime and attribution differ. The source gaps below are real; their contribution to the whole remaining gap is not yet measured.

1. Motion scoring still has fine-grained call/check boundaries and repeated source loads.
Go encoder/md.go:478 onward calls the cost callback independently for four half-pixel candidates. encoder/sample_simd.go:126-177 already validates quarter spans once and fuses average with SATD, but its loop still invokes the validated assembly callback separately four times (149-151). Each invocation reloads the encoded block. Initial search also repeatedly enters the public checked SAD callback (svc_motion_estimate.go:143,155); four-candidate SAD still marshals slice headers (common/sad_four_simd_amd64.go:9-38). Native uses raw-pointer cost callbacks (codec/encoder/core/src/md.cpp:532,575; svc_motion_estimate.cpp:222,335), avoiding Go's checked entry and slice marshaling.

Bounded next work: first benchmark a whole four-candidate half/quarter scoring helper with one validation pass and shared encoded-row loads, returning four costs. Preserve strict '<' selection, original candidate order, callback instrumentation, scratch swaps and alias fallback. Native also evaluates separate costs here: cross-candidate fusion would be a Go-specific compensation, not a missing native feature. The existing Go profile assigns 15.16% cumulative to fractional refinement and 5.24% to the already-fused quarter path; those are upper bounds on possible savings, not predicted savings. Avoid another blind SATD instruction schedule rewrite; that experiment already regressed controls.

2. Some intra prediction remains scalar even though final block rendering is SIMD.
Go encoder/get_intra_predictor_simd_amd64.go:65-89 calculates plane coefficients with scalar weighted gathers for 8 luma/4 chroma positions, then calls SIMD rendering. Native codec/encoder/core/x86/intra_pred.asm:229-311 and 320-404 also vectorize coefficient arithmetic. Go's angular I4 predictors still use scalar gathers/interpolation and temporary blocks (get_intra_predictor.go:104 onward, including DDR at159); the amd64 dispatch at get_intra_predictor_simd_amd64.go:25 has no angular I4 overrides. Native explicitly installs angular MMX kernels (codec/encoder/core/src/get_intra_predictor.cpp:698-705).

Bounded next work: complete one checked plane predictor, including coefficient reduction, then measure the whole call and whole intra mode decision; do angular I4 only if profile/bench benefit justifies each kernel. Do not redo optimized DC/H/V word stores. A separate first-three-mode predictor-plus-SAD helper might reduce Go callback/source-load overhead at svc_base_layer_md.go:572-606, but native also uses separate predictor and SAD calls, so fusion is a hypothesis rather than an identified native capability. Go plane coefficients alone are 1.09% flat; WelsMdI4x4Fast is 5.87% cumulative. This work is useful but insufficient for parity by itself.

3. Residual entropy writing remains a large scalar/stateful path; its remaining excess needs a matched whole-block benchmark.
Go set_mb_syn_cavlc.go:40-59 already inlines common writes, but each full word crosses a noinline flush, stores state through sCavlcBs and enters a checked indexed WRITE_BE_32. Native codec/encoder/core/src/set_mb_syn_cavlc.cpp:57-81 keeps pointer/accumulator/count locals and expands the complete write/flush macro inline. Packed level tables and SIMD parameter extraction are already present in Go and must not be claimed as missing. Go WriteBlockResidualCavlc is 12.72% cumulative and flush is 1.09%; native also spends substantial time in CAVLC, so the entire block percentage is not removable overhead.

Bounded next work: use identical captured coefficient blocks and initial writer states to compare whole residual writers with native. Only pursue a private amortized-check writer/local output state if this demonstrates material excess. Preserve emitted bits, overflow/error behavior and partial-flush state exactly. Prior scalar-state reshaping was rejected; merely repeating it or removing safety checks is not a justified optimization.

Conclusion
These are the strongest remaining source-backed areas, not a demonstrated explanation of every missing millisecond. Even their cumulative profile shares cannot be added freely because paths overlap. Matched per-stage/native measurements are still needed; the round-six report separately provides final end-to-end timing. Therefore claiming that these bounded changes alone deliver native parity would exceed the evidence.
