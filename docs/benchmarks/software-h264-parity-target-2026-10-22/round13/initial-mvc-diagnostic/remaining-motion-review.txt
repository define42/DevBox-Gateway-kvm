The round11 Road profile totals17.99CPU seconds; InitialPoint is1.13s cumulative

BOUNDED DESIGN / NECESSARY SAFETY
Start only with16x16 and exactlyfive MVCs. Require an exact known built-in SAD
callback identity in addition to CPU/capability gating; a marker alone must not
silently bypass newly customized five-MVC callbacks. All other shapes/counts and
custom callbacks keep the old loop with its live mutation behavior.

Clip initial+five vectors exactly as today (including int16 conversion), retain
first-occurrence order, and deduplicate equal clipped MVs before SAD. For immutable
built-in inputs and identical MVD terms, a repeated MV has identical signed cost;
best cost only decreases under strict '<', so a later duplicate can never win.
This preserves winner/tie order without searching fewer distinct positions.

Use fixed stack arrays with tracked pointers and one direct noescape raw call,
never an indirect callback receiving a local descriptor. Validate encoded visible
bytes once and each unique reference view; preserve the existing int32 offset
multiplication/addition before conversion to int. Negative/overflow/short spans
and malformed MVD indices return to the old loop before any externally observable
write, so its candidate-by-candidate panic order survives. Zero/overlapping strides
and read-only source aliases either retain exact reads or fall back. A direct raw
multi-SAD leaf can keep several independent sums and share each16-byte encoded row
across references, without modifying reference reads or the final selection math.

Preflight all unique MVD indices without indexing/panicking; on failure use legacy
before any changes. Once every read is safe and the exact SAD callback is pure,
compute costs and select in first-occurrence order with the existing int32 wrapping
and strict '<'. Invoke the directional callback once at its original point with
unchanged arguments/state, then keep UpdateMeResults and early-stop behavior.

WHY ONE MORE DIAGNOSTIC IS NEEDED BEFORE CODE
The existing counters record only skips equal to the current winner, not the
number of distinct clipped vectors. Scoring all six unconditionally would perform
~24% more SAD arithmetic on Road and~51% more on PDF. Deduplicating the six positions
should avoid that, but its benefit and average resulting batch size are unknown.
One isolated diagnostic over the same fixtures should record distinct clipped-MV
histograms for only16x16/uiMvcNum5, without changing production or timing the
instrumented build. If most have only1-2 unique vectors, plan/dispatch overhead
may outweigh batching; a blanket multi-kernel would be unjustified.

If the distribution supports it, compare the complete InitialPoint caller against
frozen source for all winner/tie/duplicate/clipping/MVD/extreme/alias/custom/partial
panic cases, with one-MVC/narrow/custom/scalar controls and local-state allocations.
Only then use paired codec/full-frame gates. This is a new experiment; prior held
16-wide four-SAD scheduling, SATD scheduling, metadata layout and narrow-copy work
are not being proposed again.
